# 固定密钥视频加密（2026-09-15）

## 已实现的行为

按“复制走的视频不能被普通播放器直接播放”的要求，采用 FFmpeg 已支持的 MP4 Common Encryption：`cenc-aes-ctr`，固定 AES-128 密钥。这里没有采用自定义文件头或整文件解密，播放器的 MOV 解复用器在读取音视频包时解密，再交给原来的软件/RKMPP 解码器。本地文件和 HTTP 点播共用此入口，支持进度跳转，不产生整部明文临时视频。

视频和所有音轨均加密，容器索引、时长等元数据仍可读取。这是防止直接复制播放的基础保护，不是 DRM 或文件完整性认证；有能力提取播放器密钥的人仍能解密。

三端位置：

- 服务器：`D:\HVIDEO\Hvideo_server`
- 播放器：`D:\CHUANGWEI`
- PAD：`D:\CHUANGWEI\Fultter_pad`

## 使用

2026-09-16 后缀更新：新工具统一输出 **`.hvideo`**（内部仍为 CENC MP4），需使用支持该后缀的服务器和播放器 1.5.6/2445。下文旧 `.mp4` 输出示例已被此约定替代；已有加密 MP4 的兼容读取保留。新命令行示例：`python scripts/encrypt_videos.py D:/原视频/12345.mkv D:/加密视频/12345.hvideo`。

图形界面 EXE 已内置 Python、FFmpeg 和 ffprobe，无需另行安装。播放器须先更新到包含本次改动的版本，然后再将加密输出加入曲库。

### 图形界面（推荐）

双击服务器目录的 **`视频加密工具.exe`**，打开中文桌面工具，不需要输入命令或密钥。可将这个单文件复制到其他 Windows x64 电脑使用；首次启动需等待内置组件解压。原 `视频加密工具.vbs` 入口优先启动 EXE。

1. 选择“单个视频”或“整个文件夹（含子目录）”。
2. 点击“浏览…”选择原视频以及输出文件夹。单文件按原文件主名输出 `.hvideo`；批量保留子目录。文件夹模式可以把输出文件夹选为原视频文件夹，原片会保留；已存在同名输出时会明确提示，不会覆盖。
3. EXE 已内置 FFmpeg，无需配置路径。工具只处理 `.mkv` 源视频，其他格式会自动忽略。
4. 点击“开始加密”。界面显示文件队列、加密/校验阶段、阶段进度与完成数量。完整校验通过后才计入完成。
5. 完成后点击“打开输出文件夹”。文件出错时停止后续任务，原因显示在下方记录区；已完成结果保留。

“停止任务”会终止当前 FFmpeg/ffprobe、等待进程退出，并清理未完成的 `.partial`。处理中关闭窗口也会先执行同样的清理，再退出窗口。原片与此前已完成文件保留。

界面使用 `scripts/video_encryption_ui.py`，直接调用原有 `scripts/encrypt_videos.py`，没有第二套加密规则、HTTP API 或密钥配置。此轮只新增服务器侧操作界面，无需重新构建播放器 APK。

### 命令行

源码命令行运行需要 Python 3、FFmpeg 和 ffprobe。

单文件（输入必须为 `.mkv`，输出为 `.hvideo`）：

```powershell
python "D:\HVIDEO\Hvideo_server\scripts\encrypt_videos.py" "D:\原视频\12345.mkv" "D:\加密视频\12345.hvideo"
```

批量处理目录（递归保留子目录和文件主名，只处理 `.mkv`，统一输出 `.hvideo`）：

```powershell
python "D:\HVIDEO\Hvideo_server\scripts\encrypt_videos.py" "D:\原视频" "D:\加密视频"
```

以上路径为使用示例，不是本次已处理的媒体目录。可用 `--ffmpeg` 和 `--ffprobe` 指定可执行文件的完整路径。

将加密输出目录设置为现有媒体目录后，使用已有扫描/匹配流程。服务器仍通过原来的 `/media/<相对路径>` 或已索引媒体路径提供文件，播放器本地缓存/下载保存的是密文。点歌、切歌、原伴唱、HTTP Range 的请求和响应字段均未新增；PAD 不持有密钥。

工具不会覆盖或删除原片；原片所在目录仍是未加密的，不能把它当作受保护的曲库。现有曲库和数据库本次均未迁移。

2026-09-15 后续更新：服务器启动会检查运行根目录下的 `freesongs`，缺失则自动创建；已有目录和文件保留。放入空闲视频后，重新保存后台空闲歌曲路径或重启播放器进行刷新。自动建目录不改动自定义空闲歌曲路径设置。

## 格式与文件处理规则

- 原码流重新封装和加密，不重新编码画面和声音；已验证 H.264、H.265、AAC 双音轨，以及纯音视频 MKV 转加密 MP4。其他编码是否能无损放入 MP4 由 FFmpeg 判断，不兼容则报错。
- 2026-09-16 更新：支持一条内嵌 ASS 歌词轨。完整 ASS（含样式、逐字高亮及时间）保存在 MP4 的 `hvideo_ass_v1` 元数据内，仍为单个视频文件；读取此歌词需要播放器 1.5.5/2444 或更新版本。其他字幕格式、多条字幕、封面附件及数据轨仍明确拒绝，不静默丢弃。章节信息不写入输出。
- 文件主名保留，便于按歌曲编号匹配；文件夹模式允许输入和输出为同一目录，因为输出 `.hvideo` 不会再次参与源文件扫描。输入与输出互为父子目录时仍会拒绝。相同目录内存在同主名、不同扩展名文件时，会预先拒绝，避免输出冲突。
- 密钥固定；每次加密的 IV 由 FFmpeg 自动生成，不启用会固定 IV 的 `bitexact` 选项。已经加密的输入会拒绝再次加密。
- 加密先写入同目录 `.hvideo-encrypt-*.partial`，验证所有音视频轨为 `encv/enca`，确认编码/轨道未变，再读取全部加密视频包并容错解码音轨进行校验。视频样本采用解密后的包复制读取，避免重复做整片软件视频解码。全部通过后才原子发布最终 MP4。不会写出完整明文视频，失败或正常取消会清理本次 `.partial`。
- 校验会读取整部影片和全部音轨；FFmpeg 的可恢复 AAC 帧错误按播放器兼容行为忽略，致命 FFmpeg/容器错误仍会失败。视频只做包级读取，不再重复完整解码。强制结束进程或断电不保证执行清理，遗留 `.partial` 不会作为视频索引。
- 批量中途失败会停止；已经成功的输出保留。2026.09.22.2 起再次运行会明确列出“已存在，已跳过”，继续加密没有输出的文件；全部输出已存在时显示“全部已存在，已跳过”。跳过只依据目标文件存在，不重新校验其内容；已有文件不会覆盖。
- 本次支持本地视频和 HTTP 点播文件；不是给 IPTV、RTSP 或 HLS 直播新增加密协议。播放器原有明文播放路径继续可用。

## 修改清单与密钥约定

服务器新增：

- `scripts/encrypt_videos.py`：单文件/目录加密、校验和安全发布。
- `scripts/video_encryption_v1.json`：v1 固定密钥、公开 KID、算法版本。这个文件仅供加密工具使用，不放入 `static` 或媒体目录，不通过 API 下发。
- `tests/test_video_encryption.py`：真实 FFmpeg 回归测试，使用自动清理的临时目录和本机临时 HTTP 服务。

播放器修改：

- `include/utils/MediaEncryptionKey.h`：与服务器 v1 配置对应的固定密钥。
- `include/utils/EncryptedMedia.h`：统一设置 `decryption_key`，沿用调用方的超时、中断和解码参数。
- `src/decoder/core/DecoderCore_OpenClose.cpp`：主视频打开及 HTTP 重试入口。
- `src/decoder/AudioOnlyPlayer.cpp`：音轨读取入口。
- `src/decoder/RkmppMpeg2Probe.cpp`：探测入口。
- `src/utils/MediaUtils.cpp`：视频信息、格式检查和缩略图读取入口。
- `docs/03-API接口规范.md`：同步工作区已有调用统计漂移（337 → 338 个 Web 调用，`GET /api/v1/config.json` 调用点 10 → 11），没有增加接口。
- `app/version.properties` 由正常构建自动递增：调试 1.4.5/2434，正式 1.4.6/2435。

v1 密钥投入使用后不要重新生成或单独改动任意一端，否则现有加密文件无法播放。密钥一致性由回归测试检查，日志、播放地址和本文档不记录密钥值。以后轮换需要新增版本并兼容旧文件，而非覆盖 v1。

此次没有修改播放器转码导出的行为；不要用其现有转码功能处理加密源。需要转换编码时，先在加密工具之外处理原片，再加密最终文件。
