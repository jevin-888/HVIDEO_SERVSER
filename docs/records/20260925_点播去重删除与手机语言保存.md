# 点播去重、删除与手机语言保存

日期：2026-09-25

## 问题与修改

- 点歌整行点击曾绕过已选状态判断；共享点歌服务也没有请求中的防重锁。现在整行和加号走同一入口，正在提交或已经入队的歌曲不能再次提交。首页和歌星歌曲页的已选按钮显示勾选并禁用，删除后可以重新点播。
- 服务端入队改为单条 SQLite 条件插入，按房间和歌曲编号检查等待/正在播放状态，避免多端同时点播同一歌曲。其他房间及已唱完、已删除歌曲可以正常点播。
- 手机已选状态按歌曲编号去重，索引、数量和按钮状态使用同一份列表。
- 删除查询原来可能命中已唱历史；现在只匹配活动队列。按歌曲编号删除会清除该歌曲在活动队列中的遗留重复行，历史记录保留；按队列记录 ID 调用仍只删除对应记录。删除正在播放行时继续原有事务内切换下一首逻辑。
- 手机启动原来强制设置中文。现在语言服务使用 `ktv:language` 保存用户选择，重新打开页面恢复所选语言，同时刷新首页、底部导航和双语提示。语言加载继续后台执行。
- API 路径及请求字段不变：POST `/api/v1/rooms/:id/queue` 使用 `songNo`；DELETE 使用队列删除端点。已唱重新点播统一经过共享服务的去重检查。
