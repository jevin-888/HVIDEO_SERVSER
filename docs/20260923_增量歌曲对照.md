# 2026-09-23 增量歌曲对照

## 功能

- 后台“歌曲路径对照”新增“对照方式”下拉框，默认全量对照，可选择增量对照。
- 全量对照保持原行为：以所选盘符重建可用歌曲索引。
- 增量对照保留未匹配歌曲的原路径、格式和可用状态，只新增或更新本次成功匹配的歌曲。空扫描或零匹配不会清空旧索引，不会清理已经失效的旧路径。
- 两种模式均按本次扫描候选的 HVIDEO → MKV → MP4 → 其他格式选择，同格式按完整路径排序；未扫描的旧文件不参与比较。增量扫描同编号新文件也会更新原有路径。
- 删除重复只作用于本次扫描中的未选副本，数据库事务提交成功后才执行；不删除未扫描的文件和未匹配文件。数据库失败时原记录完整回滚，不删除文件。
- 继承拒绝访问目录跳过规则。运行期间禁用模式、盘符和删除选项，完成或失败后恢复。

## API 一对一

- 原接口 `POST /api/v1/songdb/scan/start` 新增唯一布尔字段 `incremental`，省略为 false；原 `directory`、`deleteDuplicates` 含义不变。
- `GET /api/v1/songdb/scan/result/{task_id}` 返回任务的 `incremental`，无别名或新路由。Web API 包装与页面调用同步传递该字段。
- 源曲库、文件表、搜索/歌手可用标记和点播索引在同一事务更新。

## 修改文件

- src/models/scan_task.rs：请求与任务模式字段、严格字段解析回归。
- src/scanner/database_matcher.rs：增量不执行全量清空，原事务更新逻辑共用。
- src/services/song_path_matcher_service.rs：模式传递、增量端到端回归。

- scripts/incremental-scan-ui.test.mjs：浏览器页面/API 回归。
- docs/design/Pad服务端API一对一协议.md：更新完整请求、响应和两种模式语义。
