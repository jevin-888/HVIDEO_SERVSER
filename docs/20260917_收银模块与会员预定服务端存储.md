# 收银模块与会员预定服务端存储

## 行为

- Flutter 收银端六个管理菜单接入现有收银页面。`?desktop=1` 且存在 WebView2 消息桥时隐藏重复导航，通过 `desktop_bridge.js` 接收原生员工会话。Token 不写入 URL 或浏览器存储；普通浏览器登录方式不变。
- 会员、预定不再使用 localStorage 作为业务数据源。两端读取服务器数据库，相同服务器共享记录。WebSocket `cashier_customers_changed` 刷新内存缓存，进入页面和点击刷新也重新获取数据。
- 旧浏览器数据只由“导入本浏览器旧数据”显式读取。逐条写入，冲突不覆盖，失败项列出，原数据保留。请在原浏览器和原地址执行；不存在的房间、会员或员工引用需修正后重试。
- 卡号（不区分大小写）、手机号唯一，资料更新采用 version 防止覆盖；编辑已有会员时不能直接覆盖余额/积分，充值和扣费调用原子增减接口。余额不足拒绝扣费，request_id 重放不重复执行。
- 预定检查房间、会员、员工引用，当前一个房间最多一个有效预定；只有空闲房间可新增有效预定。取消记录保留；开房失败不将预定标为已开房。
- 会员结账扣费/积分、账单支付和房态更新同事务提交；失败回滚，已付款账单重试不再次扣款。修复原页面将会员扣款先于收款确认执行的问题。

## API（均沿用 code/message/data 封装及现有 JWT 认证）

| 方法 | 路径（/api/v1 前缀） | 用途 |
|---|---|---|
| GET/POST | /admin/members | 列表/新增或导入会员 |
| PUT/DELETE | /admin/members/:id | 修改资料/软删除（有余额或有效预定时拒绝） |
| POST | /admin/members/:id/balance | 原子充值/扣费与积分变更 |
| GET/POST | /admin/reservations | 列表/新增或导入预定（含历史状态） |
| PUT/DELETE | /admin/reservations/:id | 修改有效预定/取消 |
| POST | /admin/reservations/:id/opened | 房间开房成功后更新预定状态 |

会员提交字段：`id,card_no,name,phone,level,birthday,balance,points,remark,version`；返回增加 `created_at,updated_at`。余额请求：`request_id,balance_delta,points_delta`。金额最多两位小数，余额内部使用整数分。

预定字段：`id,room_id,room_name,room_ip,reservation_time,member_id,member_no,marketer_id,marketer_name,customer_name,phone,people,prepay,remark,status,version,created_at,updated_at`。时间使用 `YYYY-MM-DDTHH:mm`；服务端重新解析房间名、会员卡号、营销姓名；状态为 reserved/opened/cancelled。

现有 `POST /billing/sessions/:id/pay` 增加可选 `member_id`，会员支付使用 `paymentMethod: "member"`。财务查询统一使用后端已有 `roomId` 参数。
