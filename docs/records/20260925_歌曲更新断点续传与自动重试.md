# 歌曲更新断点续传与自动重试（2026-09-25）

## 问题与修复
旧版更新使用随机 TempDir，失败退出即删除已下载片段；请求不发送 Range，并用 File::create 重建文件，所以60%失败后重试从0开始。

- 使用更新目录内持久化 `.hvideo-update-<云端地址与包ID哈希>/` 缓存；`.part` 文件按清单 SHA256 区分内容。包增加视频、换任务或重启不会使相同内容失去下载进度。
- 重试发送 `Range: bytes=<已保存字节>-`，验证206的 Content-Range、总长度和内容编码；云端忽略 Range 返回200时从头安全覆盖，绝不把整文件追加到片段后。完成后对完整文件做 SHA256 校验才发布、入库。
- 网络断开、连接/读取60秒超时、HTTP 408/429/5xx 自动重试，间隔5/10/20/40/60秒，之后每60秒继续重试。手动更新模式下已发起的任务同样自动续传。
- 失败时 flush/sync 保存片段与数据库进度；暂未成功仍显示进行中，“等待自动续传”不要求客户点重试。
- 重启后待执行/运行中的任务恢复为待自动续传，由调度器自动恢复；手动模式只恢复此前发起的包，不自动下载新发布的其他包。
- 本地存在且校验正确的视频直接复用，避免重新下载或占用一份重复缓存。容量保护根据尚缺字节计算，预留10GB规则保持生效；自动换磁盘时复制已有缓存后续传。
- 完整入库成功才清理本包缓存；过程中失败会保留已完成文件和片段。换盘前的缓存本次完成后清理；如换盘过程异常退出，原盘缓存仍保留用于恢复。
- 404、授权过期/拒绝、非法Range、清单/校验不一致、磁盘/数据库错误属于需处理问题，不进行无限网络重试。SHA256不符的片段会丢弃防止污染入库；旧版本已删除的片段无法恢复。

## API约定
没有新增或变更业务API。客户端下载仍使用清单download_url和 `X-HVideo-Server-License`，续传增加标准HTTP Range头；读取并验证Content-Range与Content-Length。任务/更新记录沿用原有结构。
