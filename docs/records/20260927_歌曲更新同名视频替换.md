# 歌曲更新同名视频替换（2026-09-27）

## 日志与原因

云端更新记录中，服务器 `F990-BE56-F1BB-4807-DDF9-7A6F-6898-5D63` 连续多次在 `5,839,203,292 / 8,625,492,302` 字节（约 67.7%）失败，错误相同：

> 保存目录存在内容不同的同名文件 60000297.hvideo，请更换目录或先处理该文件

原更新器将目标目录同名且 SHA256 不同的视频直接当作错误，导致本包终止；自动调度约 5 分钟后重试仍遇到同一个文件。该错误不能据此解释为整包反复传输。

## 修改

按用户要求，同名视频以更新包中的版本为准：

- 大小与 SHA256 均相同：复用现有文件，不再下载。
- 内容不同：使用现有持久化缓存下载新版，原视频在下载、断线续传、校验及歌曲资料匹配期间保持原样。
- 新版完整且 SHA256 校验通过、歌曲资料匹配成功后，从同一磁盘缓存通过重命名直接替换目标文件。不先删除或截断旧文件，不额外留下隔离目录。
- 替换被 Windows 文件占用等错误阻止时，旧视频和已校验缓存都保留，下次重试复用缓存；成功后按原流程登记歌曲、可点播索引、加密视频评分和新歌批次。
- 删除原“同名内容不同立即失败”和只允许目标不存在时保存的分支。

仅修改 `src/services/vod_update_service.rs`；未修改业务 API、数据库结构、云端部署、自动调度间隔和 10GB 空间保护规则。

## 测试

- 混合包：同名不同内容（同大小）、相同内容、新视频共 3 个，只发起 2 次网络下载，全部保存并入库；再次执行不增加网络请求。
- 在已有旧视频时模拟下载 60% 断线和 503，旧视频保持不变，自动 Range 续传完成后替换并入库。
- 新视频 SHA256 不符时，旧视频与已登记的可点播索引不受影响。
- 真实 Windows 文件句柄禁止删除/重命名时替换失败，两份文件都保留；关闭句柄后离线复用缓存完成替换与入库。
- `cargo test --lib --locked --offline`：257 项通过，0 失败，6 项专用环境测试忽略。
- `node scripts/cloud-settings-ui.test.mjs`：通过（状态轮询、进度、自动/手动、授权、目录选择与防重复请求）。

首次定向测试中，新增占用测试在入库表尚未创建时查询该表，已改成校验源曲库 `fileExists=1` 的数量；完整回归通过。测试使用内存数据库与自动清理的临时目录，没有修改现场曲库或视频。
