# 点歌服务器云端授权模块

2026-09-24。管理入口：`/admin` → 服务器授权，独立页面 `/server-licenses`。

## 使用

管理员登录后填写点歌服务器机器码、场所资料、期限（含永久与快捷日期）、终端点数、播放器模块/图层/通道数/商业模式及可选云端更新截止日期。点击“签发并发布授权”即保存云端档案并发布，同时下载 `server.lic`。服务器启动时获取，运行期间每 60 秒复查。已有档案可搜索、按状态筛选、查看每次历史、导出某次授权并使用其资料续签。

签发范围和默认选项与 D:/HVIDEO/server_license-tool 一致。云端签发不需要打开本地工具；原本地签发工具和导入方式继续可用。线上已有真实授权不会被本次发布自动续期或改变权限。

## API 一对一协议

所有 JSON 字段使用 camelCase，播放器 license 内字段维持原 snake_case。成功响应 `{code:0,data:...}`；HTTP 错误响应含 code/message。签发和查询记录均要求有效管理员 access token，代理商与匿名用户禁止访问。

| 前端操作 / 消费者 | 方法 | 路径 | 请求 | data |
|---|---|---|---|---|
| loadArchiveRecords | GET | /api/admin/server-licenses | 无 | 历史数组，含 sequence、licenseId、machineCode、issuedAt、expiresAt、venueName、contact、phone、address、terminalLimit、license、可选 cloudUpdate、archivedAt、filePath |
| 签发按钮 | POST | /api/admin/server-licenses | requestId(UUID)、input（与本地 generate_server_license 输入完全一致） | content、licenseId、fileName |
| 下载历史 | GET | /api/admin/server-licenses/{licenseId}/file | 无 | content、licenseId、fileName |
| LicenseManager.refresh_cloud | POST | /api/server-license/resolve | machineCode、nonce(UUID) | 已签名查询响应，见下文 |

签发 requestId 实现幂等：同管理员同参数重试返回同一结果，不同参数返回 409；并发重试只插入一次。档案及最新授权均以数据库 sequence 排序，避免同秒签发和时钟变化造成顺序倒置。场所资料最长 512 字、机器码必须八组四位十六进制、点数范围 1–100000；模块/图层/通道/商业模式沿用本地验证；签发时间与服务器相差不能超过 5 分钟。云端更新日期不能超过非永久服务器期限。

签名文件继续使用 server.lic v2 原格式和 Ed25519 公钥，输出可由旧版点歌服务器导入。查询响应由同一签发密钥签名，字段为 product=`hvideo-server-cloud-response`、machineCode、nonce、serverTime、content（server.lic 文本或 null）、signature。签名使用递归对象键排序的紧凑 UTF-8 JSON，不包含 signature 字段。消费者必须同时校验签名、产品、机器码、请求 nonce、时间差（300 秒内）和 content 内独立授权签名。无档案的 null 响应也须有签名，不接受未签名 404 作为撤销/覆盖依据。

## 云端优先与本地保底

- 点歌服务器启动等待云端最多 4 秒，运行每 60 秒刷新；查询任务跟随服务器生命周期取消，响应限制 64 KiB。
- 已验证云端授权优先，单独缓存为 `license/server-cloud.lic`；原 `license/server.lic` 保留不覆盖。
- 云端无档案：使用原本地授权。网络错误/超时/错误签名：保留上次验证的缓存；没有缓存时用原本地授权。
- 云端最新授权到期后，在线及断网缓存均保持到期，不借旧文件恢复权限。所有保底授权继续核验签名、机器码和期限。
- 缓存写入失败时仍在当前进程使用已验证的云端结果，状态 cloudMessage 返回写入失败；下次联网继续重试缓存。
- `/api/v1/license/status` 增加 source（cloud/cloud_cache/local）、cloudConnected、cloudCheckedAt、cloudMessage。HTTP 查询/导入、终端准入、PAD/播放器授权契约保持原接口。
- 管理登录页和设置页显示授权来源，每 30 秒刷新。导入本地文件若云端优先仍有效，会明确提示本地文件已保存而当前使用云端。

## 部署与密钥

云端私钥放宿主机 `/opt/license-server/secrets/server-license.key`（目录和文件限制访问，文件 600），Compose 只读挂载到 `/run/secrets/server-license.key`。可用 SERVER_LICENSE_SIGNING_KEY_FILE 指定其他文件路径。启动其他云端功能不依赖密钥，未配置时签发/查询返回 503。私钥不进入网页、源码、Docker 镜像或更新包；密钥公钥必须与已有 server.lic 公钥一致。

新增独立表 server_license_records，服务启动创建；不修改现有播放器设备授权表。数据库日常备份应包含此表，签发密钥需另外保管。部署沿用 deploy-incremental.ps1：先 -BuildOnly，隔离验证，再正常增量启动。增量打包文件改为时间戳名称，避免不同发布互相覆盖。
