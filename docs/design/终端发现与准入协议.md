# 终端注册与网络连接协议

硬件序列号 `serial` 是数据库识别物理播放器的固定身份，注册时必填；IP 是随设备当前连接实时更新的地址，不作为固定身份或注册租约。同一播放器通过有线或无线网络上报时必须使用相同序列号，只保留一个终端 ID、一个自动创建的房间和一个授权名额。内置有线网卡 MAC 随同一序列号的最新有效上报更新；连接类型和当前网卡 MAC 单独保存。

## 身份和校验

- 序列号来自 Java/硬件信息，不使用 IP、MAC 或临时生成值代替。服务端去除首尾空白，统一为大写，忽略大小写查重。
- 有效序列号长度 4–128，只允许 ASCII 字母、数字、`-`、`_`、`.`，至少包含一个字母或数字。拒绝全零、全 F，以及 `unknown`、`null`、`none`、`default`、`serial`、`0123456789ABCDEF` 等占位值。
- 顶层 `macAddress`（UDP 为 `mac`）始终为内置 `eth0` MAC，即使本次通过 Wi-Fi 发送也保持相同。不根据当前链路切换设备绑定 MAC。
- `network.macAddress` 是本次发送网卡的实际 MAC，可以与顶层设备 MAC 不同。Wi-Fi 使用实际当前地址，包括系统启用的随机地址。
- MAC 拒绝全零、Android 占位 `02:00:00:00:00:00`、广播和组播地址，允许合法的本地管理地址。
- 接受型号 `H6`、`H6_...`、`H6-...`，比较时忽略大小写。
- 序列号或设备有线 MAC 暂未就绪时，播放器等待重试，跳过发现广播与响应，不创建占位终端。

## HTTP 准入

`POST /api/v1/terminals/admission` 使用服务端的 `code/message/data` 响应格式。请求仅接受以下 camelCase 字段，不支持别名：

```json
{
  "protocolVersion": "2.0",
  "deviceRole": "player",
  "appId": "com.hsvj.engine",
  "deviceName": "HSVJ Player",
  "macAddress": "D6:AB:AA:8A:53:7F",
  "serial": "279F4F6D53F8FEBE",
  "model": "H6_POR",
  "softwareVersion": "1.0.6",
  "httpPort": 8080,
  "network": {
    "networkType": "wifi",
    "interfaceName": "wlan0",
    "macAddress": "84:93:EC:D5:73:A5"
  }
}
```

`protocolVersion`、`deviceRole`、`appId`、`macAddress`、`serial` 必填，`model` 必须是支持的型号。`deviceName`、`softwareVersion`、`httpPort` 可省略。新版播放器始终携带 `network`；为滚动升级保留旧版 v2 省略该字段的情况，服务端将其标记为 `unknown`。

`network` 对象恰好包含 `networkType`、`interfaceName`、`macAddress` 三个必填字段。允许的组合只有 `ethernet` + `eth0`、`wifi` + `wlan0`；客户端不能提交 `unknown`，不能在此对象中提交 IP。有线连接 MAC 必须与顶层设备 MAC 一致。

播放器在 TCP 建立后，根据该 socket 的本地地址构造 `network`。服务端从 TCP 对端读取 IP，不接受请求体指定终端 IP。

成功响应 `data` 字段为：`authorized`、`switchToOnlineVod`、`terminalId`、`terminalLimit`、`registeredTerminals`、`remainingPoints`、`expiresAt`、`serverTime`、`contractVersion`（2）、`issuedAt`、`permanent`、`customerName`、`license`。成功时 `switchToOnlineVod=true`；名额不足的拒绝响应为 false。缺失字段、非法序列号/MAC/网卡或不支持的型号返回 `400`；授权不足返回 `403`；序列号或 MAC 身份绑定的冲突返回 `409`，失败不新增终端、房间或连接。

## 服务器回复与自动在线 VOD（2026-09-17）

播放器启动时使用临时 UDP socket，从 eth0/wlan0 发送已有播放器 Beacon，最多等待 1.2 秒。正常运行后的 3 秒 Beacon 继续用于网络稍后就绪的情况。服务器登记成功后向数据包的真实来源 IP/端口定向回复，不伪装为播放器广播：

```json
{"type":"hvideo_server","protocol":"online_vod","protocol_version":"2.0","device_role":"server","app_id":"com.hvideo.server","terminalSerial":"279F4F6D53F8FEBE","serverPort":9898,"switchToOnlineVod":true}
```

回复恰好包含上述 8 个字段。播放器核对身份、协议、目标序列号（忽略大小写）和固定 VOD 端口 9898，地址只取 UDP 来源 IP；不接受 payload 指定地址。最多缓存 4 个来源，15 秒失效。

该标志只触发现有 HTTP admission，不等于授权。HTTP 准入成功且 `switchToOnlineVod=true` 后，播放器写入 `vodMode=2`、`enableVod=true`、`onlineVodHost=<实际联系服务器>`、`onlineVodRoomId=current`。已有配置只原子更新这些字段，其他设置保留；写入失败不改变运行模式；首次无文件则由正常默认配置创建流程一起保存。已处于相同服务器的在线模式时不重复写盘、不覆盖手工房间设置。

已有服务器地址优先尝试；成功接入后固定该服务器，不因另一台服务器回复而来回切换。未准入时约每 5 秒重试候选服务器，正常准入后约每 30 秒续验。启动时网络未就绪，收到后续 Beacon 回复也会在渲染线程切换，停止本地 VOD 自动播放并初始化在线队列。无服务器、授权拒绝或缺少标志时保留原配置。本地授权优先规则不变。

旧播放器忽略新增回复和字段；新播放器仍能按既有配置连接旧服务器，但旧服务器不会触发自动切换。PAD API 无变化。

## 手动注册和扫描

`POST /api/v1/terminals/register` 需要 JWT，请求必须且只能包含：

```json
{"terminalIp":"192.168.2.101","serial":"279F4F6D53F8FEBE"}
```

服务器向该 IP 发起 UDP challenge-response，并将用户填写的序列号与播放器实际返回的序列号核对。缺失或无效序列号返回 `400`，与实际设备不一致返回 `409`。

`POST /api/v1/terminals/discover` 和周期扫描使用相同握手。序列号从已验证的播放器响应取得，缺少有效序列号不能注册。

## UDP 与 HTTP 字段对应

UDP 协议版本保持 `2.0`，端口 `18080`。顶层沿用 UDP 原有 snake_case，嵌套 `network` 与 HTTP 完全一致，不增加字段别名。

| 含义 | UDP 发现 | HTTP 准入 |
|---|---|---|
| 协议版本 | `protocol_version` | `protocolVersion` |
| 设备角色 | `device_role`，固定 `player` | `deviceRole`，固定 `player` |
| 应用标识 | `app_id`，固定 `com.hsvj.engine` | `appId`，固定 `com.hsvj.engine` |
| 设备有线 MAC | `mac` | `macAddress` |
| 设备名称 | `device_name` | `deviceName` |
| 硬件序列号 | `serial`，必填 | `serial`，必填 |
| 型号 | `model` | `model` |
| 软件版本 | `version` | `softwareVersion` |
| HTTP 端口 | `ports.http` | `httpPort` |
| 本次连接 | `network`，同一三字段对象 | `network`，同一三字段对象 |

UDP `ports` 恰好包含 `http`、`mobile`、`vod`、`ws`、`tcp`、`udp`、`sync`；`sync` 为 `4322` 或未启用时的 `0`。完整发现包另包含 `type=hvideo`、`protocol=discover`、`ip`，主动查询响应还包含原样返回的 `challenge`。

播放器每 3 秒从每个可用的物理网卡各发一次 Beacon；使用 `IP_PKTINFO` 绑定实际发送接口和源地址，响应查询时沿收到查询的接口返回。服务器只采用 UDP 数据包源地址，不信任 JSON 自报 IP。

播放器 `GET /api/v1/system/discovery` 使用同一构造器，按实际 HTTP socket 的设备端地址提供 `network`；身份或连接信息未就绪返回 `503`。此播放器接口仍使用播放器自己的 `ok/data/error` 响应封装。

## 列表、连接和在线状态

`GET /api/v1/terminals`、`GET /api/v1/terminals/:id`、手动注册和终端更新返回的 `Terminal` 新增顶层 `serial`、`connections`，其余字段保持原名。顶层 `terminalIp` 和 `port` 指向当前优先连接；顶层 `macAddress` 保留设备有线 MAC。

房间与其绑定设备共用后台设置的名称。`POST /api/v1/rooms` 的 `name`、`PUT /api/v1/rooms/:id` 或 `PUT /api/v1/terminals/:id` 显式提交的 `name`，去除首尾空白后在同一事务中保存到房间和终端，空名称返回 `400`。只更新状态、音量等字段且未提交 `name` 时保留名称。终端尚未绑定房间时可单独改名；历史多房间绑定的终端改名返回 `409`。客户端仍只发送原有请求，名称字段固定为 `name`，响应结构保持不变。

改名成功后沿用 `terminals_updated` 事件（`{"type":"terminals_updated"}`）通知终端列表刷新，关联房间沿用房态同步。设备后续通过 HTTP 准入或 UDP 发现上报旧设备名时保留后台名称。首次自动创建的房间仍使用“房间-设备名”，显式保存名称后使用后台设置的名称。

每个 `connections` 元素恰好包含：`terminalId`、`networkType`、`interfaceName`、`ipAddress`、`macAddress`、`port`、`onlineStatus`、`lastHeartbeat`、`createdAt`、`updatedAt`。每台终端按 `networkType` 保留一条当前/最近连接记录，时间由服务器记录。

- 管理列表每台设备一条，展开固定显示有线和无线；没有报告的网卡显示“未上报”，不会推断其地址。旧版 v2 的未分类连接另显示“未识别的连接”。
- 各连接独立记录心跳，60 秒无心跳视为失效，后台每 30 秒检查一次；注册/心跳到达时也检查该设备已有连接。
- 有任一有效连接则设备在线。有线和无线同时在线时优先有线，不因报文先后反复切换主 IP。有线失效后使用无线，有线恢复后切回有线。
- 两个有效地址都能解析到同一个终端和房间。WebSocket 内部频道以及 `/api/v1/system/ws/connections` 返回的 `roomId` 使用稳定房间 ID，切换网络不会改变频道。断开一个 WebSocket 不直接把设备标记离线。
- 删除终端时，在同一事务中删除该终端的连接、关联房间和队列。授权仍按物理终端数量计数。

## 迁移和冲突

迁移 `035_terminal_network_connections` 从旧 `hardwareInfo.serial` 回填唯一且有效的序列号，保留终端 ID、房间和授权计数。历史报文未包含网络类型，因此旧地址迁为 `unknown`，收到明确报告后再归类。

迁移 `036_sync_room_terminal_names` 将历史上已修改的房间名同步至唯一绑定的终端，修复例如房间为 `VIP888` 而终端仍为 `localhost` 的记录。自动房间名（含旧随机后缀）、空名称和多房间歧义绑定不参与回填。

历史重复序列号不自动合并或删除；再次注册时返回冲突。历史记录尚无有效序列号时，只允许以原绑定有线 MAC 补录序列号。同一序列号上报新的有效有线 MAC 时，在同一事务内更新原终端及有线连接 MAC，保留终端 ID、房间、名称和授权名额；清除旧的未分类连接。若新 MAC 从无线连接上报，旧有线连接先标记离线，待有线心跳确认地址后恢复，避免继续使用旧 IP。新 MAC 已属于其他序列号、连接 MAC 已属于其他设备、重复历史序列号及非法 MAC 仍拒绝并回滚。Wi-Fi MAC 变化只更新该设备的无线连接。

迁移 `037_reclaim_expired_terminal_ips` 保留非空主 IP 的唯一索引，允许多台设备的主 IP 为空。它不修改既有序列号、MAC、房间或授权计数。

每次通过 UDP 发现/心跳或 HTTP 准入确认设备身份后，按 `serial` 查找原设备，并立即采用实际 UDP 源地址或 TCP 对端地址更新对应网卡的 IP。相同序列号重复上报或更换 IP 仍使用同一终端、房间和授权名额。已有记录的 IP、在线标记和最近心跳时间均不阻止实时更新；不再等待旧连接 60 秒超时。

当 IP 的最新有效上报属于另一个序列号时，在同一事务内将旧设备该 IP 对应连接标记离线并将 IP 关联到本次上报的设备。旧设备其他有效连接继续保留；两个设备互换 IP、连续换 IP 都按各自序列号更新。并发上报按事务提交顺序处理，最后提交的有效上报持有该地址，数据库始终只有一个当前归属。历史连接保留原地址供查看，但不参与占用判断。60 秒超时仅用于在线状态检测和主网卡失效切换。

释放地址和新连接注册在同一事务中完成，身份校验失败、授权不足或数据库写入失败全部回滚。旧设备另有有效连接时重新选择主连接，否则将已让出的 `terminalIp` 清为空字符串并标记离线。不会把新设备的旧 IP 猜测分配给旧设备，也不会合并或删除设备、房间、序列号或授权名额。新旧设备的房间缓存均同步更新，沿用 `terminals_updated` 通知。注册、离线检测和房间管理的缓存刷新串行读取数据库当前状态，避免较早请求的旧快照在并发更新后写回旧 IP。

旧设备暂时没有主 IP 时，管理端仍可编辑设备和房间；更新房间缓存后跳过要求实际 IP 的播放器状态广播，避免已保存却返回错误。播放器状态 API 仍要求有效 IP，不伪造字段。

`terminalIp` 字段仍为字符串：非空时为实际 IPv4，已释放且无替代地址时为 `""`；管理列表显示 `-`。历史地址仍可在离线 `connections` 中查看。空地址不能用于查找终端、房间或 WebSocket 身份，不写入 `offline:...` 占位值。


## 播放器授权范围（v2）

服务器管理端的“系统设置 → 服务器授权信息 → 导入/更新授权”支持在有效授权期间续期、更换点数或更新播放器权限；未授权时仍可从登录页导入。两个入口共用 `POST /api/v1/license/import`，请求体仅为 `{ "content": "授权文件文本" }`，成功后使用响应中的授权状态刷新界面，无需重启服务。文件必须在服务器本机导入，后台继续校验签名、机器码、有效期和权限；拒绝无效文件时保留原授权。

`license` 原样来自服务器已验证签名的 `server.lic`，恰好包含 `modules`（字符串数组）、`enabled_layers`（整数数组）、`input_channel_count`（非负整数，0 不限）、`usage_mode`（buyout/rent/installment）。嵌套字段与本地 `license.dat` 保持一致，不接受 enabledLayers 等别名；图层不可为空，模块可为空。模块 ID：TV、投屏、霸屏、fusion、effects。图层 ID 与播放器 LayerDefinitions 一致。

播放器所有模式优先有效本地授权；没有有效本地文件时访问配置的点歌服务器。网络点歌的终端准入、点数校验与权限来源分开处理，准入不会覆盖本地权限。服务器有效期和永久标记由服务器计算；普通授权使用服务器时间加单调运行时计时，到期即停止授权播放。

旧版 v1 server.lic 不含播放器权限，准入返回 403 并提示重新签发。新旧服务器与播放器必须配套升级。未准入每 5 秒重试，已准入每 30 秒核验；短暂断网保留进程内授权至期限，明确拒绝撤销服务器权限；重启不读取缓存服务器权限。

播放器 `GET /api/v1/system/license` 额外返回 `license_source`（local/server/none）和 `last_error`，原模块、图层和输入通道字段继续反映当前生效权限。导入有效 license.dat 后立即优先本地；错误导入保留原授权。
