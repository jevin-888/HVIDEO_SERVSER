# 2026-09-16 歌曲对照同步视频格式与路径

## 问题与行为

此前对照成功只写入歌曲路径和可用状态，源曲库 videoFileType 仍可能是旧格式，导致后续点播队列带有旧格式信息。

- 对照成功后，从最终选中的文件后缀生成小写格式值（HVIDEO → hvideo），在同一 SQLite 事务内更新 songs 的 videoFileType、absolutePath、relativePath、fileName 和可用状态；同步 songFiles 的绝对/相对路径、文件名，以及 local_available_songs 的实际点播路径和文件名。
- 重复文件仍按现有去重规则选定文件，格式以最终选定文件为准；无匹配记录不建立孤立的可用索引。
- 新点播读取 videoFileType 与 local_available_songs.absolutePath 改为单条 SQL 的同一快照，再写入主库 room_queue 的 video_file_type、songPath，避免对照恰好提交时分别读出不一致的格式/路径。
- 任一写入失败整批回滚。没有新增数据库列或 HTTP/JNI/API 字段。
- 当前源曲库与可点播对照实际在同一个 song_db/song.db：songs 保存格式唯一值，local_available_songs 保存可用路径；无需再复制一套格式字段。data/hvideo.db 的 room_queue 在新点歌时写入同步后的格式/路径。已有正在播放或排队的歌曲快照不在扫描中重写。

## 为什么暂不删除格式字段

本地播放器解码依赖实际媒体内容，普通文件后缀可以推导显示格式。但是视频格式字段还用于后台/API、源数据导入时拼接文件名、点播队列，以及 youtube 来源分流。直接删字段会影响这些现有行为。因此保留兼容字段，成功对照时自动维护，用户无需再手工改格式。
