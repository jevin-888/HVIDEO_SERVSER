## 已修正的确定问题

- 原桌面端只有托盘/IPC 手动重启，没有进程外守护；整个进程退出后无法自救。新增共用的 `src/process_guard.rs`，由同一个 EXE 的轻量父进程监控工作子进程，桌面端和独立服务器入口均接入。
- 异常退出按 3、6、12、24、48、60 秒退避重试，上限 60 秒；运行满 60 秒后重置连续故障计数。正常退出码 0 停止守护，现有 `relaunch_app` 通过退出码 75 请求父进程立即重启，删除旧的 cmd/start 拉起逻辑。
- 使用操作系统文件锁防止同一运行目录重复启动。正常运行会有两个同名进程：守护进程和实际工作进程。
- 桌面内嵌后端线程结束后自动恢复，复用手动重启互斥锁；开发环境 `SKIP_BACKEND=1` 不接管外部后端。
- 原停止流程超时后丢失旧线程句柄，可能再启一个后端。现在一直保留句柄直到线程确实退出，再回收并启动新线程；等待被取消时也保留句柄。
- HTTP 服务运行错误原本被日志记录后吞掉，最终返回成功；现在清理连接后向调用方返回原错误。
- 新增 `logs/crash.log`（panic 位置、线程及堆栈）、`logs/process-stderr.log`（隐藏进程标准错误）和 `logs/watchdog.log`（启动 PID、退出码、重试间隔）。原业务日志仍为 `logs/server.log`。
- 托盘退出先请求停止后端，最长等待 20 秒，再正常结束。主窗口关闭仍按原行为收起到托盘。

## 根因复核（2026-09-15）

通过便携版日志与 Windows System/Application 事件按时间对齐，确认 03:44 的退出由操作系统重启引起：

- `logs/watchdog.log`：03:44:09 子进程退出，随后记录重启尝试；退出码 `0x40010004`，之后系统关机阶段子进程返回 `0xc000026b`。
- Windows 事件 1074（03:44:09）：`C:\WINDOWS\uus\AMD64\MoUsoCoreWorker.exe` 以“Service Pack（计划内）”代表 SYSTEM 发起重启。
- Windows UpdateClient 事件 43/19（03:44:21—03:44:39）：正在安装并完成 Intel Corporation System/MEDIA Driver Update。
- Kernel-Power 事件 109（03:44:59）：`Power Action Reboot`；Kernel-General 事件 13（03:45:01）确认系统关闭；03:45:30 系统重新启动。

因此本次没有服务器 Rust panic、业务异常或端口冲突，属于 Windows Update 安装驱动后的计划重启。服务器已在系统恢复后重新启动，`http://192.168.2.11:9898/health` 返回 200。
