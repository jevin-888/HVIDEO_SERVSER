# 客户端磁盘容量同步到云端服务器授权页（2026-10-01）

## 功能

客户端 HTTP 服务启动完成后在后台采集磁盘空间，随后每 60 秒重新读取当前配置并随授权查询上报。每盘记录盘符/挂载点、总字节数、可用字节数，同时记录绝对更新目录及该目录当前可用空间。采集只读，不扫描媒体、不创建目录、不写探测文件。磁盘枚举使用独立阻塞任务，每次等待最多 2 秒；慢盘任务未完成时不会反复生成新任务，授权查询照常进行。原启动授权获取不等待磁盘采集。

云端服务器授权管理表新增“磁盘空间”列：更新目录、目录可用容量、上报时间；展开显示每盘总容量/剩余空间及已用进度条，低于 10GB 标红。列表仍每 15 秒刷新，展开状态保留，不干扰授权表单输入。离线/上报超时显示“上次上报”，旧客户端显示“尚未上报”。

客户端必须安装本次新 EXE 才会上报；云端发布本身不会让旧软件自动具备采集功能。

## API 与数据库

扩展已有 POST /api/server-license/resolve，原 machineCode/nonce 保留，新增可选 storage：

```json
{"disks":[{"mountPoint":"D:/","totalBytes":2147483648000,"availableBytes":107374182400}],"updateDirectory":"D:/歌曲更新","updateAvailableBytes":107374182400}
```

storage 可省略（旧客户端或采集不可用）；updateAvailableBytes 允许 null，表示目录容量无法读取。最多 64 个磁盘，每盘剩余不得超过总量，不允许重复挂载点，校验字符串长度及数值范围。原有授权查询的机器码登记契约保持兼容，磁盘数据仅为客户端自报运行信息，不能赋予授权，也不影响签名许可验证。

云端增加独立 server_storage_reports 表（machine_code、payload、received_at），启动幂等建表，按机器码替换最近一次快照；旧客户端未带 storage 时保留快照，不重置磁盘上报时间。GET /api/admin/server-registrations 新增 storage 和 storageReportedAt，未上报为 null，仅管理员可读。授权档案与签名内容不增加磁盘数据。
