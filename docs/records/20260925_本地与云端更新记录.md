# 本地与云端更新记录（2026-09-25）

## 行为
- 本地云端更新页面新增“更新记录”；云端后台新增“服务器更新记录”，服务器授权表每一行也可查看该服务器记录。
- 每次更新生成独立 UUID，重试保留原失败记录。保存包名称、类型、版本、清单指纹、视频数量、成功入库数、下载进度、目录、开始/结束时间及结果原因。
- 本地 SQLite `update_history` 独立于任务和更新包，不级联删除。触发器与任务进度/结束结果同事务保存。
- 每 15 秒自动补报（手动/自动下载模式都生效），网络故障不改变下载结果。序号与已确认序号组成持久化待报队列。云端 MySQL `server_update_records` 按服务器签名 ID + 尝试 UUID 去重，只接受更新序号。
- 云端只接收签名授权中的服务器 ID，不接收客户端自报 ID。允许过期签名授权用于补报历史，不允许其下载视频或获得新授权。
- 页面每 15 秒自动刷新，可按包名称/结果筛选和分页；云端还可按服务器 ID 筛选。展开详情时暂停刷新，避免阅读被打断。
- 原 `sync_tasks` 可恢复的数据迁移为历史记录；缺失的原始清单/视频数显示“—”，已经被旧版重试覆盖的历史无法恢复。旧时间保持当时本地时间，新时间以 UTC 储存并按浏览器时区显示。

## 一对一 API
- 本地 GET `/api/v1/cloud/update-history`：管理员读取本地历史；查询 `page`（20条/页）、`status`（-1或0..3）、`package`。结果含 `items,total,page,pageSize`，额外字段 `cloudSynced` 表示当前序号已上报。
- 云端 POST `/api/server-update-records/report`：请求头 `X-HVideo-Server-License`，JSON 字段 `id,taskId,packageId,packageName,packageType,versionCode,packageRevision,videoCount,importedCount,fileSize,downloadedSize,status,localPath,message,startedAt,updatedAt,finishedAt,sequence`。未知字段拒绝；响应 `data:{id,sequence}` 确认请求序号已处理（旧序号不会覆盖新数据）。
- 云端 GET `/api/admin/server-update-records`：管理员查询；本地查询参数加 `machineCode`，结果记录额外含 `machineCode,receivedAt`。
- 状态：0等待、1更新中、2完成、3失败；失败时入库数量为空表示没有成功完成/核验整包，不能当成0或承诺全部回滚。
