# 独立守护程序（2026-09-15）

## 行为

- 用户仍启动 `release/HVideo_Admin_Portable_0.2.0/HVideo Admin.exe`。启动入口带起同目录的 `hvideo-watchdog.exe` 后退出，守护再启动实际工作进程。稳定运行时为一个主程序、一个独立守护，不再有两个同名主程序。
- 守护只依赖共享进程协议和时间库，不加载 Tauri、WebView2、业务数据库和 HTTP 服务。
- 守护持有真实子进程句柄；工作进程退出后立即获知结果。首次异常立即重启；连续不足 60 秒的失败才按 3、6、12、24、48、60 秒延迟，防止启动失败导致高速循环。稳定运行 60 秒后重置计数。
- 托盘“退出”先写入本轮、当前 PID 专属的主动退出通知，再停止后端并退出。守护收到该通知、确认进程结束后同步退出，不拉起。每一轮使用不同通知文件，读取后删除，旧通知不会影响下一次启动。
- 退出码 0 本身不再视为人为关闭：没有主动退出通知就会恢复。任务管理器/外部程序强制终止不能可靠区分操作者意图，因此一律按异常恢复；要停服请用托盘“退出”。
- 原有应用重启请求（退出码 75）继续立即重启；后端重启仍只重启内嵌服务。窗口右上角关闭仍收起到托盘。
- 守护锁及工作进程锁共同防止重复服务。若仅守护被外部强杀而主程序仍存活，新的启动请求不会创建第二个工作进程；应先退出原主程序再启动。
- Windows 进入关机状态时停止拉起。不阻止系统重启，不代替开机自启，不保证断电、同时强杀守护与主程序、系统任务对象整体终止时仍能恢复；进程存活但卡死不在本次监控范围。

## 日志和原生诊断修正

- `logs/watchdog.log` 记录独立守护 PID、目标 EXE、工作目录、工作进程 PID、启动轮次、十进制/十六进制退出码、运行时长、是否收到人为退出通知及重试间隔。
- `logs/process-stderr.log` 收集主程序标准错误，`logs/crash.log` 收集 Rust panic 和可捕获的 Windows 未处理异常。
- 修正上一版 `MiniDumpWriteDump` 错把 `EXCEPTION_POINTERS` 直接作为参数传入的问题，改用按 Windows ABI 对齐的 `MINIDUMP_EXCEPTION_INFORMATION`。同时记录 dump 写入成功/失败、异常码和异常地址。
- 原生异常处理为尽力采集；内存/栈严重损坏、fail-fast、系统强杀或子级 WebView2 进程崩溃不保证走本进程处理器，不能承诺所有情况都有 dump。

## 修改范围与构建

- `src/process_guard.rs`：共享守护协议与诊断；删除旧的同名 EXE 常驻守护路径。
- `watchdog/`：独立轻量 Rust 项目、锁文件及真实进程测试夹具。
- `src-tauri/src/main.rs`：托盘退出通知；`src/main.rs`：独立后端接入原生诊断与 Ctrl+C 退出通知。
- `scripts/build_watchdog.ps1`：构建并将守护复制到桌面端/后端构建目录。
- `package.json`、`src-tauri/tauri.conf.json`、`scripts/build_portable.ps1`：开发、打包、安装资源带上守护。手工运行 cargo 构建主程序前，先运行 `pwsh -File scripts/build_watchdog.ps1 -Release`（调试构建省略 `-Release`）。
- 未修改 HTTP、WebSocket、Tauri IPC 请求或响应，PAD—服务器—播放器 API 不变。
- 三端目录：服务器 `D:\HVIDEO\Hvideo_server`，播放器 `D:\CHUANGWEI`，PAD `D:\CHUANGWEI\Fultter_pad`。
