## 问题一：开机权限脚本破坏升级状态目录

优先级：高，影响升级成功确认、回报、清理和后续 ROM 检查。

- /huoshan/.rom-update 已被改成 system:system、0777，内部文件为 system:system、0666。
- 正常状态命令 `su 0 /system/bin/hsvj-rom-update --status` 返回 `staging ownership invalid`，退出码 1。
- status.json 停留在 phase=installed，message=awaiting Android boot verification，version_code=33。
- 状态记录的 Recovery boot ID 为 8eee09fa-2be9-4dfe-a884-cab03c716c36，当前 Android boot ID 为 78b462d8-ad48-46ba-a4fd-b722cbb6ad32。
- update.img 仍占用 854798922 字节，服务器 data/rom-results 尚无升级结果。
- Recovery pstore 显示 hsvj-rom-update 请求重启；结合仅在分区写入及读回校验完成后写入 installed 的实现，确认镜像安装阶段已完成，但 Android 首启确认未完成。

根因：Android 源码 vendor/chuangwei-minimal-perf/hsvj_perf_tune.sh 第 128 至 134 行递归修改整个 /huoshan 的属主和权限。控制器 system-integration/hsvj-rom-update/rom_update.cpp 第 114 行要求升级目录为 root 所有，Java RomUpdateManager 在检查流程开始时调用状态入口，因此被阻断。

修复方向：开机脚本排除受保护的 .rom-update 子树，并对已受影响设备设计状态验证与权限恢复。保持控制器的 root 属主校验；不能通过放宽校验消除报错。

## 问题二：系统选择了不存在的 dex2oat32

优先级：中，影响应用优化，可能增加启动和运行成本。

- installd 报错：execv(/apex/com.android.art/bin/dex2oat32) failed: No such file or directory。
- Engine、ExtServices、Tethering、MediaProvider 等包的 dexopt 失败。
- 设备仅有 dex2oat64，CPU ABI 为 arm64-v8a，dalvik.vm.dex2oat64.enabled 属性为空。
- Engine 的 dexopt 状态为 run-from-apk，播放器仍可运行。
- frameworks/native/cmds/installd/dexopt.cpp 第 443 至 451 行默认选择 dex2oat32，仅在 dalvik.vm.dex2oat64.enabled=true 时切换。

修复方向：在此纯 64 位 ROM 的配置中正确启用 dex2oat64，重新构建后验证系统应用 dexopt 成功。缺少旧 ROM 同项检查基线，暂不判断此问题是否由本次升级引入。
