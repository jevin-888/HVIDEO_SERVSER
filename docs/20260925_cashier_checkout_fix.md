# 收银结账编号与页面账单不同步修复

现场已显示正确金额，收款仍提示“请先查询账单”。旧版支付依赖共享 window.currentBillingSessionId，房态异步查询可以清空/覆盖它，而页面仍显示之前的金额。回归测试清空这个共享编号后，旧代码无法进入收款确认；修复后取消/确认和实际模拟支付均通过。

结账页面保存独立账单快照，核对房间、会话状态及 API 字段后才启用收款。付款使用同一快照的 id；确认期间换房或退出会取消提交。账单失败显示实际错误及重新查询按钮，未加载、加载失败、错房间和过期响应均不能付款。中/印尼/越南/泰/英同步提示。API 沿用 GET /api/v1/billing/room-bill?roomId=... 与 POST /api/v1/billing/sessions/:id/pay，无服务端 Rust 或数据库结构修改。

部署：解压 HVideo-Cashier-Server-Resources-20260925.zip，将其中 static 合并到现场实际运行的服务器 EXE 同目录，覆盖对应文件。包不包含数据库、config.toml、授权或服务器 EXE。不要删除其余 static 资源。配套收银端 v1.0.4 刷新页面缓存，退出重开收银软件后生效。

回归在 Edge 无头浏览器的隔离模拟 API 中执行，不对现场账单付款、不修改营业数据。覆盖共享编号丢失/篡改、查询失败重试、错误房间、迟到响应、现金找零及不足额、收款确认取消、会员付款、开房/点单/打印/转房及权限。

验证结果：cashier-actions-ui.test.mjs、cashier-desktop-ui.test.mjs 通过；5 项 Flutter 桥接测试通过，包含发送 F4 后使用当前选中房间进入 checkout。F4 与鼠标结账按钮使用相同业务入口。dart analyze 无问题；配套 v1.0.4 正式构建成功，完整客户端 ZIP 25 文件逐项校验通过。服务器包 8 个静态资源均与源码及本机 HTTP 服务内容哈希一致。
