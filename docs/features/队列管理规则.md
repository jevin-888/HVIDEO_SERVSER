# 队列管理规则

## 歌曲状态定义

### status 字段
- `0`: 等待播放
- `1`: 正在播放（队列中的第一首）
- `2`: 已播放完成
- `3`: 已跳过

### 队列规则
1. **第一首歌**：`status=1` 正在播放
2. **第二首歌**：`status=0` 下一曲（待播放）
3. **其他歌曲**：`status=0` 等待播放

## 接口行为

### 1. 清空队列 (POST /api/v1/rooms/:id/clear)

**行为**：
- 只删除等待播放的歌曲（`status=0`）
- **保留正在播放的歌曲**（`status=1`）
- 不清空 `current_song_id`

**SQL**：
```sql
DELETE FROM room_queue WHERE room_id = ? AND status = 0
```

**使用场景**：
- 用户想清空队列但继续播放当前歌曲
- 重新开始点歌但不中断当前播放

### 2. 打乱队列 (POST /api/v1/rooms/:id/queue/shuffle)

**行为**：
- 只打乱等待播放的歌曲（`status=0`）
- **排除正在播放的第一首**（`status=1`）
- 保持正在播放歌曲的 position 不变

**逻辑**：
1. 获取正在播放歌曲的 position（如 position=1）
2. 随机打乱 status=0 的歌曲
3. 将打乱后的歌曲 position 设置为从 position+1 开始

**使用场景**：
- 用户想随机播放队列中的歌曲
- 不影响当前正在播放的歌曲

### 3. 置顶歌曲 (POST /api/v1/rooms/:id/queue/prioritize)

**行为**：
- 将指定歌曲插队到**下一曲位置**（第二位）
- 设置 `is_priority=1`
- 重新排序其他歌曲

**逻辑**：
1. 查找正在播放的歌曲（status=1）
2. 将置顶歌曲的 position 设置为 playing.position + 1
3. 重新排序所有歌曲：
   - 正在播放的保持第一位
   - 置顶的歌曲排在第二位
   - 其他歌曲按原顺序排列

**使用场景**：
- 用户想让某首歌下一个播放
- VIP 用户插队点歌

### 4. 切歌 (POST /api/v1/rooms/:id/next)

**行为**：
1. 将当前播放的歌曲标记为已跳过（`status=3`）
2. 获取下一首等待播放的歌曲（`status=0`）
3. 将下一首歌曲标记为正在播放（`status=1`）
4. 更新房间的 `current_song_id`

**排序规则**：
```sql
ORDER BY is_priority DESC, position ASC
```
- 优先播放置顶的歌曲（`is_priority=1`）
- 然后按 position 顺序播放

### 5. 删除歌曲 (DELETE /api/v1/rooms/:id/queue/:song_id)

**行为**：
- 从队列中删除指定歌曲
- 可以删除任何状态的歌曲（包括正在播放的）

**注意**：
- 如果删除正在播放的歌曲，需要前端调用切歌接口播放下一首

## 数据库结构

### room_queue 表

```sql
CREATE TABLE room_queue (
    id TEXT PRIMARY KEY,
    room_id TEXT NOT NULL,
    song_id TEXT NOT NULL,
    song_title TEXT NOT NULL,
    artist_name TEXT NOT NULL,
    position INTEGER NOT NULL,
    status INTEGER DEFAULT 0,  -- 0:等待 1:播放中 2:已完成 3:已跳过
    is_priority INTEGER DEFAULT 0,  -- 0:普通 1:置顶
    added_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 查询队列

```sql
SELECT * FROM room_queue 
WHERE room_id = ? AND status IN (0, 1) 
ORDER BY 
    CASE WHEN status = 1 THEN 0 ELSE 1 END,  -- 正在播放的排第一
    is_priority DESC,  -- 置顶的排前面
    position ASC  -- 按position排序
```

## 测试场景

### 场景1：清空队列
```
初始状态：
1. 后来(MTV) [播放中]
2. 成都(MTV)
3. 我怀念的(MTV)

执行清空后：
1. 后来(MTV) [播放中]
```

### 场景2：打乱队列
```
初始状态：
1. 后来(MTV) [播放中]
2. 成都(MTV)
3. 我怀念的(MTV)
4. 西海情歌(MTV)

执行打乱后：
1. 后来(MTV) [播放中]  ← 不变
2. 西海情歌(MTV)  ← 随机
3. 成都(MTV)  ← 随机
4. 我怀念的(MTV)  ← 随机
```

### 场景3：置顶歌曲
```
初始状态：
1. 后来(MTV) [播放中]
2. 成都(MTV)
3. 我怀念的(MTV)
4. 西海情歌(MTV)

置顶"西海情歌"后：
1. 后来(MTV) [播放中]
2. 西海情歌(MTV) [下一曲] ← 插队到第二位
3. 成都(MTV)
4. 我怀念的(MTV)
```
