# 2026-09-17 终端 MAC 自动更新与系统设置显示

## 用户要求

同一播放器序列号上报新的 MAC 后，服务器更新原登记；Android TV 系统设置状态页应显示设备实际 MAC。

## 服务器修改

- `TerminalService::register` 按序列号复用终端，接受新的有效内置有线 MAC；原终端 ID、名称、房间和授权名额保留。
- 有线连接 MAC 同步刷新；经无线/旧版报文更新有线 MAC 时，未确认的旧有线连接先离线，删除过时的 unknown 连接，避免旧地址继续被选为主连接。
- 同序列号旧版报文在已知有线连接上仍更新新 MAC，不保留旧 MAC。
- 新 MAC 属于另一终端、网卡字段不一致、非法 MAC 或历史重复序列号仍拒绝；验证及所有更新在同一事务内完成。
- MAC 变化触发既有 `terminals_updated` 刷新链路。没有新增或改名 API 字段；协议文档同步更新。

## 系统设置修改

ROM 源码：`D:/HVIDEO/HSVJ/android11-hsvj-src`（完整源码在 WSL 的 ext4 挂载中）。

根因：TvSettings 状态页的“设备 MAC 地址”实际调用 `WifiManager.getFactoryMacAddresses()`，没有读取有线网卡；Wi-Fi 关闭时可能没有可用工厂地址。

替换 Wi-Fi 专用控制器为 `DeviceMacAddressPreferenceController`，优先读取 `NetworkInterface.getByName("eth0").getHardwareAddress()`；无有效有线地址才回退到 Wi-Fi 工厂地址。过滤空值、零地址、Android 占位地址及组播地址；进入页面和网络状态变化时刷新。清理已无引用的旧控制器，同步 XML preference key。

修改记录、原始源码备份、构建日志、APK 和实机截图：`D:/HVIDEO/HSVJ/records/20260917-device-mac-settings/`。
