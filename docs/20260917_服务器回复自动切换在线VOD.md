# 2026-09-17 服务器回复自动切换在线 VOD

## 需求与实现

播放器无需预填服务器 IP。启动时发送现有 UDP 上线 Beacon，服务器登记通过后向实际来源定向回复在线 VOD 标志；播放器再进行 HTTP 准入，成功才改模式并持久化配置。

- UDP 18080：新增服务器专用回复 `hvideo_server / online_vod / 2.0`，包含服务器角色、应用 ID、目标终端序列号、serverPort=9898、switchToOnlineVod=true，共 8 个字段。服务器 IP 只取报文来源，避免信任 payload 地址。回复不作为授权凭证。
- HTTP `POST /api/v1/terminals/admission`：响应新增布尔 switchToOnlineVod，授权成功为 true、名额拒绝为 false；其他字段、签名授权验证及本地授权优先规则保留。
- 播放器从关闭/单机模式接入后保存 vodMode=2、enableVod=true、onlineVodHost、onlineVodRoomId=current。已有 config.json 只修改这些字段，沿用 FileUtils 原子写入；保存失败保留原运行模式和文件。没有文件时由正常默认配置创建流程统一保存。
- 启动临时 UDP socket 最多等待 1.2 秒，之后释放。正常发现服务每 3 秒广播，收到后续回复仍可自动接入；候选来源最多 4 个、15 秒失效。已有地址优先尝试，成功后不随其他回复来回切换。未准入约 5 秒重试、成功后约 30 秒续验。
- 运行中切换在渲染线程执行，停止本地点歌自动播放、初始化在线队列并启用网络 VOD 服务。启动阶段等待配置和图层初始化完成后才处理后台回复。运行中切换不会热覆盖图层模板；完整启动模板在下次启动加载。
- 无服务器、拒绝准入、身份不符、缺少标志或非标准 9898 端口回复不触发自动配置。原来已配置的在线模式仍保留。重复成功响应不重复写盘，也不覆盖已经选择的房间。
- 旧播放器忽略新增回复和字段；新播放器按原配置连接旧服务器仍兼容，但自动切换需要同时更新两端。PAD 不修改。
